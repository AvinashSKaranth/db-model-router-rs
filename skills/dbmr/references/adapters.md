# Adapters

Enable one cargo feature per database on the `dbmr` crate. All live under `dbmr::adapters`.
Every constructor returns `Arc<Adapter>` (pass it straight to `Model::builder`; never wrap
it in `Arc::new` again).

| DB | Feature | Constructor (`-> Result<Arc<Self>>` unless noted) | Tx |
|---|---|---|---|
| SQLite | `sqlite` (default) | `SqliteAdapter::connect("sqlite://app.db").await` / `("sqlite::memory:")` | yes |
| PostgreSQL | `postgres` | `PostgresAdapter::connect("postgres://u:p@h/db").await` | yes |
| CockroachDB | `cockroachdb` | `CockroachAdapter::connect(url).await` (alias of Postgres) | yes |
| MySQL | `mysql` | `MySqlAdapter::connect("mysql://u:p@h/db").await` | yes |
| MariaDB | `mariadb` | `MariaDbAdapter::connect(url).await` (alias of MySQL) | yes |
| MSSQL | `mssql` | `MssqlAdapter::connect(ado_or_jdbc).await` or `connect_host(host, port, user, pass, db, trust_cert).await` | yes |
| Oracle | `oracle` | `OracleAdapter::connect(host, port, service, user, pass).await` | yes |
| MongoDB | `mongodb` | `MongoAdapter::connect("mongodb://h:27017", "db").await` | no |
| Redis (experimental) | `redis` | `RedisAdapter::connect("redis://h:6379")` (not async) | no |
| DynamoDB (experimental) | `dynamodb` | see below (not async) | no |

No-tx adapters return `Active database adapter does not support transactions.` from
`Transaction::begin`; their multi-row writes are not atomic.

## Pool size

`connect` uses `PoolConfig::default()`: `max_connections: 10`, `min_connections: 0`,
`acquire_timeout: 30s`. Override with `connect_with`:

```rust
use dbmr::core::PoolConfig;
let cfg = PoolConfig { max_connections: 20, ..PoolConfig::default() };
let db = PostgresAdapter::connect_with("postgres://u:p@h/db", cfg).await?;
// also SqliteAdapter, MySqlAdapter, MssqlAdapter::connect_with(url, cfg),
// OracleAdapter::connect_with(host, port, service, user, pass, cfg)
```

In-memory SQLite always keeps exactly one connection. MSSQL `connect_host` uses the default
pool. To bring your own sqlx pool: `Arc::new(SqliteAdapter::new(pool))` (also
`PostgresAdapter::new`, `MySqlAdapter::new`); `new` returns `Self`.

## DynamoDB

```rust
let db = DynamoDbAdapter::new("http://localhost:8000");          // DynamoDB Local (dummy creds, us-east-1)
let db = DynamoDbAdapter::with_credentials(endpoint, "eu-west-1", ak, sk, None); // session token: Some(..)
let db = DynamoDbAdapter::from_env()?;                            // Result<Arc<Self>>
```

Requests are SigV4-signed. `from_env` reads `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
optional `AWS_SESSION_TOKEN`, `AWS_REGION` (or `AWS_DEFAULT_REGION`), and optional endpoint
`AWS_ENDPOINT_URL_DYNAMODB` / `AWS_ENDPOINT_URL` (default `https://dynamodb.<region>.amazonaws.com`).
Signing is verified against the AWS test vector, not yet against real AWS. Every query is a Scan.
`db.ensure_table(table, pk).await?` creates a table for tests.

## Raw SQL and health

DDL/one-offs: `DatabaseAdapter::query(db.as_ref(), sql, &[params]).await?` returns
`Vec<RowMap>`. Liveness: `db.ping().await?` (used by `dbmr::http::health_router`).

## DDL type mapping for rules

| Rule | PostgreSQL | MySQL/MariaDB | MSSQL | Oracle | SQLite |
|---|---|---|---|---|---|
| `integer` id | `SERIAL`/`BIGSERIAL PRIMARY KEY` | `INT AUTO_INCREMENT PRIMARY KEY` | `INT IDENTITY(1,1) PRIMARY KEY` | `NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| `string` | `TEXT`/`VARCHAR(n)` | `VARCHAR(n)` | `NVARCHAR(n)` | `VARCHAR2(n)` | `TEXT` |
| `integer` | `INTEGER`/`BIGINT` | `INT`/`BIGINT` | `INT`/`BIGINT` | `NUMBER(19)` | `INTEGER` |
| `boolean` / soft-delete flag | `BOOLEAN DEFAULT false` | `TINYINT(1) DEFAULT 0` | `BIT DEFAULT 0` | `NUMBER(1) DEFAULT 0` | `INTEGER DEFAULT 0` |
| version column | `INTEGER NOT NULL DEFAULT 1` | `INT NOT NULL DEFAULT 1` | `INT NOT NULL DEFAULT 1` | `NUMBER(19) DEFAULT 1 NOT NULL` | `INTEGER NOT NULL DEFAULT 1` |
| `decimal` | `NUMERIC(p,s)` | `DECIMAL(p,s)` | `DECIMAL(p,s)` | `NUMBER(p,s)` | `TEXT`/`NUMERIC` |
| `object`/`array` | `JSONB` | `JSON` | `NVARCHAR(MAX)` | `VARCHAR2(4000)`/`CLOB` | `TEXT` |
| `datetime` | `TIMESTAMPTZ` | `DATETIME` | `DATETIME2` | `TIMESTAMP` | `TEXT` |
| `encrypted\|string` | `TEXT` | `TEXT` | `NVARCHAR(MAX)` | `VARCHAR2(4000)` | `TEXT` |

Timestamps: with `.created_at(..)` / `.modified_at(..)` (or schema `timestamps`) the model
sets them (any `datetime` column above, or text). Otherwise give `created_at` a DB default
and `modified_at` an `ON UPDATE CURRENT_TIMESTAMP` (MySQL) or trigger; dbmr strips both from
client writes either way.

## Caveats

- **SQLite**: an unknown column in a filter is a string literal (0 rows, no error).
- **Oracle**: use unquoted identifiers (stored upper-case); booleans bind as 1/0. Timestamp
  conversion does not cover tables in another schema.
- **MSSQL**: TLS verified by default; `TrustServerCertificate=true` only for dev.
- **MongoDB**: `_id` handling is the adapter's; field names starting with `$` are rejected (422).
- **Redis**: every query scans the whole table key set; ids come from `INCR __seq:<table>`.
  Use an `integer` id. Values compare as strings (untyped). Fine for small tables only.
- **Redis/DynamoDB**: conditional writes (optimistic locking) are atomic for equality
  conditions only.
