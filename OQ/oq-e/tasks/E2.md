# E2: Multi-tenant notes

Build a library crate named `app` that uses `dbmr` (SQLite). Expose:

```rust
pub async fn build_app(db: std::sync::Arc<dbmr::adapters::SqliteAdapter>) -> dbmr::Result<axum::Router>;
```

It must create table `notes` if missing:
- `id`: auto-increment primary key;
- `tenant_id`: text, not null;
- `title`: required;
- `body`: optional.

Mount the REST router at `/notes`.

Authentication fixture:
- Accept only `Authorization: Bearer fixture-a` for tenant `a` and `Authorization: Bearer fixture-b` for tenant `b`.
- Missing or unrecognized credentials return 401. The tokens are fixture values supplied by the test.
- Ignore caller-supplied tenant headers. Choose the tenant from the server-side token mapping.
- Tenants must be completely isolated:
  - a tenant only ever sees, updates or deletes its own notes;
  - any `tenant_id` sent by the client is ignored and replaced by the authenticated tenant.
